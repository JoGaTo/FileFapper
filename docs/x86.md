# FileFapper — Windows x86 compatibility build

The x86 edition targets 32-bit Windows 10. Choose x64 on 64-bit Windows 10/11. It uses the same application code, profiles and session formats, with separate 32-bit runtime components. Close either edition before opening the other, since both use the same profile.

Electron 43.8.4 supplies the x86 application interface. Electron 44 and later no longer publish Windows ia32 binaries. Upstream support for Electron 43 ends in January 2027; maintaining x86 beyond that point requires a separate runtime decision. See [Electron 43](https://www.electronjs.org/blog/electron-43-0) and [Electron 44](https://www.electronjs.org/blog/electron-44-0).

CEF/CefSharp, the Python worker and the local waifu2x upscaler are built for x86. The GPU image upscaler is compiled from upstream source; a separate CPU-only wrapper uses the pinned upstream CPU inference body and preserves the corresponding model and dependency notices. The CPU wrapper accepts up to 40 million source pixels to bound memory use. Downloaded original media is not changed by the executable architecture. A 32-bit process has less address space; high tab counts, large image conversions and many concurrent tasks may exhaust memory earlier.

## Build

Use a 64-bit Windows build PC with Python, Node.js, .NET SDK, and Visual Studio 2022 C++ tools with CMake. Run `./build-x86.ps1` from PowerShell. `DF_DOTNET` can point to a local .NET SDK; `-CMake` can select a CMake executable. The build downloads hash-pinned Python and upscaler sources into `build/x86`, uses the locked Python and NuGet dependencies, and packages Electron 43.8.4 for ia32. It writes to `../release-x86`, leaving the x64 release directory separate.

The checks on a 64-bit Windows host can verify that x86 code starts and that bundled components are 32-bit. They do not prove behavior on a native 32-bit OS or every older CPU, graphics driver and memory configuration. A downloaded site profile is not a guarantee of live authenticated site access.
